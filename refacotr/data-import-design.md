# 데이터 임포트 설계

## 배경

고객이 기존 부품/BOM 데이터를 Fabbit에 마이그레이션하는 시나리오를 통합 설계한다.
고객의 엑셀 형태를 변경 없이 그대로 업로드할 수 있도록, LLM 기반 컬럼 매핑을 모든 케이스에 적용한다.

---

## 용어 정의

| 용어 | 정의 |
|------|------|
| **부품 마스터** | 부품 속성 목록. BOM 관계 없음 |
| **BOM** | 특정 부품(루트)의 하위 구성 목록. 항상 루트 부품 기준 |
| **Single-level BOM** | 직접 하위 1단계만 |
| **Multi-level BOM** | 전체 계층 전개 (레벨 번호로 표현) |
| **Flat BOM** | 계층 무시, 최하위 부품 수량 합산 |

> "Full BOM"은 표준 용어가 아니다. 여러 BOM을 관계 테이블로 합친 형태일 뿐이며, 별도 양식으로 취급하지 않는다.

---

## 업로드 케이스 전체 목록

### Case 1. 부품 마스터 업로드

**진입점**: 부품 목록 화면

**고객 데이터 예시**:
```
품번, 품명, 재질, 단위, 공급업체, 단가, 비고
PRT-001, 브라켓, SS400, EA, 한국정밀, 12000, 지지용
PRT-002, 드라이브 샤프트, AL6061-T6, EA, 삼성기계, 45000, 메인 구동축
```

**처리 흐름**:
1. 엑셀 업로드
2. LLM 컬럼 매핑 (기존 기능)
3. 부품 일괄 생성
4. 공급업체 등 관계 데이터가 있으면 함께 생성

**LLM 판별 결과**: `property_mappings`만 존재, `relation_mappings`에 `CONSISTS_OF`의 `node_columns` 없음

**현재 상태**: ✅ 구현 완료

---

### Case 2. BOM 업로드 (단일 부품 기준)

**진입점**: 부품 상세 화면 → BOM 탭

**고객 데이터 예시**:
```
품번, 품명, 수량, 단위, 재질, 공급업체
PRT-001, 브라켓, 2, EA, SS400, 한국정밀
PRT-002, 드라이브 샤프트, 1, EA, AL6061-T6, 삼성기계
```

**처리 흐름**:
1. 부품 상세 화면에서 엑셀 업로드
2. **루트 = 현재 보고 있는 부품** (컨텍스트로 해결)
3. LLM 컬럼 매핑
4. 하위 부품 생성 (없으면) + BOM 관계 생성

**BOM 종류별 대응**:

| BOM 종류 | 특징 | LLM 판별 기준 |
|----------|------|-------------|
| Single-level | 직접 하위만 나열 | 레벨 컬럼 없음, 상위품번 없음 |
| Multi-level | 레벨 번호로 계층 표현 | `레벨`/`Level` 컬럼 존재 |
| Flat | 최하위 부품만 수량 합산 | Single-level과 동일 형태 (구분 불필요) |

**LLM 판별 결과**: `CONSISTS_OF` rootless (상위품번 없이 수량만 존재)

**현재 상태**: ❌ 미구현

---

### Case 3. BOM 파일 일괄 업로드 (마이그레이션)

**진입점**: 부품 목록 화면 → 일괄 임포트

**고객 데이터 예시**:

파일에 상위-하위 관계가 명시된 형태:
```
상위품번, 상위품명, 하위품번, 하위품명, 수량, 단위, 재질
ASM-001, 메인 프레임 조립품, PRT-001, 브라켓, 2, EA, SS400
ASM-001, 메인 프레임 조립품, PRT-002, 샤프트, 1, EA, AL6061-T6
PRT-001, 브라켓, PRT-005, 볼트, 4, EA, SCM435
```

**처리 흐름**:
1. 엑셀 업로드
2. LLM 컬럼 매핑 → `CONSISTS_OF`에 `node_columns` 존재 확인
3. 파일 종류 자동 판별: **"부품 마스터"인가 "BOM"인가**
4. 상위-하위 관계에서 루트 자동 판별 (다른 행의 하위에 나오지 않는 품번 = 루트)
5. 모든 부품 생성 + BOM 관계 생성

**LLM 판별 결과**: `CONSISTS_OF`에 `node_columns.part_number`가 매핑됨 (상위품번 존재)

**현재 상태**: ❌ 미구현 (기존 매핑은 부품 마스터만 고려)

---

### Case 4. 폴더 일괄 업로드 (마이그레이션)

**진입점**: 부품 목록 화면 → 폴더 임포트

**고객 데이터 예시**:
```
📁 ASM-001/
   ├── 조립도.dwg
   ├── 전개도면.pdf
   └── bom.xlsx          ← BOM 파일
📁 PRT-001/
   ├── 상세도.dwg
   └── 하위부품.csv       ← BOM 파일 (파일명 비정형)
📁 PRT-002/
   └── 도면.pdf           ← 도면만
```

**처리 흐름**:
1. 폴더 구조 업로드 (zip 또는 드래그앤드롭)
2. **폴더명 → 부품 품번**으로 부품 생성
3. 각 파일 분류 (LLM 판별):
   - 도면 파일 (dwg, dxf, step, pdf 등) → 부품에 첨부
   - 스프레드시트 파일 (xlsx, csv) → BOM인지 판별 후 처리
4. BOM 파일 발견 시 → **해당 폴더 부품이 루트** → Case 2와 동일하게 처리
5. 중복 부품 처리 (여러 폴더 BOM에서 같은 하위 부품 등장 → 품번 기준 1회만 생성)

**파일 분류 기준**:

| 분류 | 판별 방법 |
|------|----------|
| 도면 파일 | 확장자 기반 (dwg, dxf, step, iges, stl, pdf 등) |
| BOM/마스터 | 확장자 (xlsx, csv, xls) + LLM 내용 분석 |
| 기타 문서 | 위에 해당하지 않는 파일 → 부품 첨부 문서 |

**현재 상태**: ❌ 미구현

---

### Case 5. Multi-level BOM (레벨 번호 포함)

**진입점**: Case 2 또는 Case 3의 변형

**고객 데이터 예시**:
```
레벨, 품번, 품명, 수량, 단위, 재질
0, ASM-001, 메인 프레임 조립품, 1, EA,
1, PRT-001, 브라켓, 2, EA, SS400
2, PRT-005, 육각볼트 M10, 4, EA, SCM435
2, PRT-006, 스프링 와셔 M10, 4, EA, SUS304
1, PRT-002, 드라이브 샤프트, 1, EA, AL6061-T6
2, PRT-007, 키 5x5x25, 1, EA, S45C
```

**처리 흐름**:
1. LLM이 `레벨` 컬럼을 식별
2. 레벨 번호로 부모-자식 관계 재구성:
   - 레벨 0 = 루트
   - 레벨 N 행의 부모 = 바로 위에 있는 레벨 N-1 행
3. 부품 생성 + BOM 관계 생성

**LLM 판별 결과**: `레벨`/`Level`/`Lvl` 컬럼이 매핑됨 → Multi-level BOM으로 판별

**현재 상태**: ❌ 미구현

## LLM 파일 종류 판별

기존 LLM 매핑 결과에서 파일 종류를 판별할 수 있다:

| 판별 조건 | 파일 종류 |
|----------|----------|
| `CONSISTS_OF` 관계 없음 | **부품 마스터** |
| `CONSISTS_OF` rootless (상위품번 없음, 수량만 존재) | **BOM** (루트 지정 필요) |
| `CONSISTS_OF`에 `node_columns.part_number` 존재 | **BOM** (상위-하위 관계 포함, 루트 자동 판별) |
| `레벨` 컬럼 매핑됨 | **Multi-level BOM** (레벨로 계층 재구성) |

### 온톨로지 확장 필요 사항

현재 `ManufacturingOntology`에 **레벨(Level)** 속성이 없다.
Multi-level BOM 대응을 위해 `CONSISTS_OF` 관계 또는 별도 메타 속성으로 레벨 개념 추가 필요.

```java
// CONSISTS_OF 또는 별도 매핑 힌트로 추가
property(
    "level",
    "BOM 레벨",
    PropertyDataType.INTEGER,
    false, false, false,
    "Multi-level BOM에서 계층 깊이를 나타내는 번호. 0=루트, 1=직접 하위, 2=손자 ...",
    List.of("0", "1", "2"),
    List.of("'레벨'", "'Level'", "'Lvl'", "'단계'")
)
```

## 중복 처리 규칙

여러 BOM에서 같은 품번이 등장할 수 있다:
- `ASM-001/bom.xlsx` → PRT-003 볼베어링 4EA
- `ASM-002/bom.xlsx` → PRT-003 볼베어링 2EA

**규칙**:
1. 품번 기준으로 부품은 **1회만 생성**
2. 이미 존재하는 부품이면 **속성 업데이트 여부를 사용자에게 확인**
3. BOM 관계는 **각각 생성** (ASM-001→PRT-003, ASM-002→PRT-003)

## 구현 우선순위

| 순서 | 케이스 | 이유 |
|------|--------|------|
| 1 | Case 2. BOM 업로드 (단일 부품) | 가장 자연스러운 UX, 루트 결정이 간단 |
| 2 | Case 3. BOM 일괄 업로드 | 마이그레이션 핵심 기능 |
| 3 | Case 5. Multi-level BOM | Case 2,3의 변형, 레벨 파싱 로직 추가 |
| 4 | Case 4. 폴더 일괄 업로드 | 파일 분류 + 모든 케이스 통합, 가장 복잡 |

> Case 1 (부품 마스터)은 이미 구현 완료

## 기존 코드 영향 범위

### 변경 필요
- `ManufacturingOntology`: 레벨 속성 추가
- `system.st` (매핑 프롬프트): 파일 종류 판별 지시 추가
- `MappingService` / `PreviewMappingUseCase`: BOM 종류별 분기 처리
- `ConfirmMappingUseCase`: BOM 관계 생성 로직 추가

### 신규 필요
- `ImportFileType` enum: `PARTS_MASTER`, `BOM`, `MULTI_LEVEL_BOM`
- `BomImportService`: BOM 임포트 전용 서비스
- `FolderImportUseCase`: 폴더 업로드 유스케이스
- `FileClassificationService`: 파일 분류 서비스 (확장자 + LLM)
- Multi-level BOM 레벨 → 트리 변환 유틸리티
