⏺ "부품번호"(URL에 들어가는 값) 기준으로 답하겠습니다.

선택지 3가지

1. 부품번호 입력 시 특수문자 제한 (가장 단순)

허용: A-Z a-z 0-9 - \_ .만 허용하고, /, #, ?, &, 공백 등은 거부.

- 장점: URL 문제 원천 차단
- 단점: Fabbit은 Excel에서 부품번호를 가져오는 구조 — 이미 /가 포함된 데이터가 들어올 수 있음. 사용자에게 "품번 바꾸세요"라고 할 수는 없음

2. Path param + URL 인코딩

ABC/123 → /parts/ABC%2F123

- 단점: 실제로 안 됩니다. Nginx, uvicorn 등 많은 서버가 path 내 %2F를 /로 디코딩해서 라우팅을 깨뜨림. FastAPI도 기본적으로 path parameter에서 /를 세그먼트 구분자로
  처리함

3. Query param으로 조회 (권장)

GET /parts?part_number=ABC/123-#4

- /든 #든 ?든 query string에서는 URL 인코딩이 정상 동작
- 단, 이러면 URL이 다시 안 예뻐짐...

현실적 추천

Path param을 유지하되, 실제 데이터를 먼저 확인하는 게 맞습니다.

제조업 부품번호에서 실제로 흔한 문자:

┌──────┬───────────┬───────────────────┐
│ 문자 │ 빈도 │ URL 문제 │
├──────┼───────────┼───────────────────┤
│ - │ 매우 흔함 │ 없음 │
├──────┼───────────┼───────────────────┤
│ . │ 흔함 │ 없음 │
├──────┼───────────┼───────────────────┤
│ \_ │ 흔함 │ 없음 │
├──────┼───────────┼───────────────────┤
│ 공백 │ 가끔 │ %20으로 처리 가능 │
├──────┼───────────┼───────────────────┤
│ / │ 드묾 │ path에서 문제 │
├──────┼───────────┼───────────────────┤
│ # │ 매우 드묾 │ fragment로 해석 │
└──────┴───────────┴───────────────────┘

질문

1. 현재 적재된 데이터에 /나 # 포함된 부품번호가 실제로 있나요? — 있으면 대응 필요, 없으면 당장은 신경 안 써도 됩니다
2. Excel 임포트 시 부품번호 검증이 현재 있나요? — 있다면 거기에 URL-safe 규칙을 추가하는 게 가장 자연스럽습니다
