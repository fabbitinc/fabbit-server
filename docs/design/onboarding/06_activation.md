# 🚀 Step 6: 활성화 및 탐색 (Activation & Exploration)

본 문서는 구축된 지식 그래프의 품질을 검증하고, AI를 통해 자연어로 데이터를 탐색하며 실질적인 비즈니스 통찰을 얻는 최종 단계를 정의합니다.

---

## 1. 개요 (Overview)

데이터 지식화가 완료된 후, 사용자는 더 이상 엑셀을 뒤지지 않습니다. 대신 AI와 대화하며 복잡한 공급망과 BOM 구조를 탐색합니다. 이 단계의 목표는 데이터의 신뢰성을 확인하고 첫 번째 'Aha-moment'를 제공하는 것입니다.

---

## 2. 주요 기능 및 화면 구성

### 2.1 데이터 헬스 체크 리포트 (Health Check Report)

지식화 완료 즉시 노출되는 대시보드입니다. 그래프 구조에서 발견된 데이터의 결함을 AI가 보고합니다.

- **누락 탐지**: "BOM에는 존재하지만 상세 정보(Part 노드)가 없는 부품 12개"
- **고립 노드**: "어떤 프로젝트나 조립체에도 소속되지 않은 부품 5개"
- **도면 부재**: "승인 상태이지만 도면 파일이 연결되지 않은 품목 8개"
- **효과**: 사용자는 자신의 데이터가 얼마나 불완전했는지 깨닫고, 시스템을 통해 데이터를 보완할 동기를 얻음.

### 2.2 AI 대화형 질의 인터페이스 (Conversational AI)

자연어를 Cypher 쿼리로 변환하여 지식 그래프를 탐색하는 핵심 UI입니다.

- **자연어 질의**: "재질이 SUS304인 부품들 중에서 납기가 가장 오래 걸리는 공급사가 어디야?"
- **추천 질문(Starter)**: 사용자가 무엇을 물어볼지 모를 때 가이드 제공.
  - _"이 프로젝트에서 단가가 가장 높은 상위 5개 품목 보여줘"_
  - _"A 공급사가 망했을 때 영향을 받는 모든 프로젝트 리스트 뽑아줘"_

### 2.3 시각화 및 영향도 분석 (Visualization & Impact)

- **BOM 트리 뷰**: 계층 구조를 시각적으로 확장/축소하며 탐색.
- **영향도 하이라이트**: 특정 노드 선택 시 연결된 모든 상위 조립체나 도면을 강조 표시 (Traceability).

---

## 3. AI 통찰력 추출 로직 (Insight Engine)

1. **질의 해석**: 사용자의 자연어 질문을 `Base Ontology` 기반으로 분석.
2. **Cypher 생성**: LLM이 지식 그래프의 스키마를 바탕으로 최적의 Cypher 쿼리 생성.
3. **결과 해석**: DB에서 반환된 그래프 데이터를 사용자 친화적인 자연어와 표, 혹은 차트로 변환.

---

## 4. 사용자 인터랙션 흐름 (User Journey)

1. **완료 알림**: "지식 그래프 구축 완료! 3,450개의 데이터 연결이 형성되었습니다." 알림 확인.
2. **리포트 검토**: 헬스 체크 리포트를 통해 데이터 누락분 확인 및 보완.
3. **첫 질문 던지기**: AI가 추천하는 질문 중 하나를 클릭하여 결과 확인.
4. **심화 탐색**: 반환된 결과 내의 특정 부품을 클릭하여 해당 부품과 연결된 공급사, 도면, 하위 BOM 정보를 꼬리에 꼬리를 물고 탐색.

---

## 5. 기술적 구현 상세 (Technical Details)

### 5.1 Graph-to-Text (RAG 확장)

- 단순히 DB 값만 보여주는 것이 아니라, 그래프의 경로(Path) 정보를 LLM에 전달하여 "왜 이런 결과가 나왔는지" 설명하게 함.
- 예: "A 부품은 B 프로젝트의 핵심 모듈인 C 조립체에 포함되어 있기 때문에 중요합니다."

### 5.2 보안 질의 (Secure Query)

- 모든 생성된 Cypher 쿼리는 실행 전 `WHERE` 절에 테넌트 격리 조건이 포함되어 있는지 최종 검증.
- 읽기 전용(Read-only) 세션에서 실행하여 데이터 변조 방지.
