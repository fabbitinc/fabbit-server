# 🏗️ fabbit 온보딩 및 데이터 지식화 Flow

본 문서는 사용자가 `fabbit`에 처음 진입하여 자신의 제조 데이터를 지식 그래프(Knowledge Graph)로 전환하고 첫 번째 통찰을 얻기까지의 전체 여정을 정의합니다.

---

## 1. 전체 온보딩 시퀀스 (High-level Sequence)

| 단계       | 프로세스 명칭                 | 주요 활동                                   | 기술적 구현                      |
| :--------- | :---------------------------- | :------------------------------------------ | :------------------------------- |
| **Step 1** | **계정 및 워크스페이스 생성** | 이메일 기반 가입 및 조직(Organization) 생성 | 자체 DB (`public` 스키마)        |
| **Step 2** | **테넌트 프로비저닝**         | 전용 DB 스키마 및 AGE 그래프 자동 생성      | `create_graph()`, 스키마 생성    |
| **Step 3** | **데이터 업로드**             | 기존 보유 엑셀(BOM, 도면 리스트 등) 업로드  | S3/Local 저장 및 메타데이터 기록 |
| **Step 4** | **AI 매핑 및 사용자 검토**    | AI의 매핑 초안(Preview) 확인 및 유저 수정   | LLM 분석 & Mapping UI            |
| **Step 5** | **데이터 지식화 (Ingestion)** | 데이터 정제, 엔티티 병합, 관계 생성         | 백그라운드 워커 (Task)           |
| **Step 6** | **활성화 및 탐색**            | 지식 그래프 검증 및 자연어 질의 시작        | Cypher 변환 & LLM                |

---

## 2. 단계별 상세 계획

### [Step 1-2] 초기 셋업 (Initial Setup)

- **자체 인증 시스템:** Clerk 등 외부 솔루션 없이 `public` 스키마의 `users`, `organizations` 테이블을 통해 직접 관리.
- **즉시 격리:** 조직 생성과 동시에 `tenant_{org_id}` 스키마가 생성되며, 해당 스키마 내에 `projects`, `folders` 테이블 및 Apache AGE 전용 그래프 공간이 확보됨.

### [Step 3-4] 데이터 인입 및 AI 매핑 (Interactive Mapping)

이 단계는 AI가 제안하고 사용자가 검토하는 **Human-in-the-Loop** 과정입니다.

1. **AI Preview 분석**: 업로드된 파일의 헤더와 샘플 데이터를 LLM이 분석하여 `Base Ontology`의 어떤 속성에 해당하는지 매핑 초안을 작성.
2. **사용자 인터페이스**:
   - 사용자는 AI가 제안한 매핑 결과를 UI 상에서 드롭다운으로 수정 가능.
   - 정의되지 않은 컬럼은 자동으로 `_ext_` (확장 속성) 접두사가 붙어 저장됨을 안내.
3. **매핑 확정**: 사용자가 '확인' 버튼을 누르면 최종 매핑 JSON이 테넌트 DB에 저장되고 실제 인제스션 프로세스가 트리거됨.

### [Step 5] 데이터 지식화 및 합성 (Data Synthesis)

대량의 데이터를 그래프 구조로 변환하는 백그라운드 작업입니다.

- **진행 상황 안내**:
  - 단순 대기 화면 대신 "현재 1,200개의 부품 노드 생성 중", "공급사 관계 350개 연결 중" 등의 실시간 진행률을 시각화.
- **엔티티 병합 (Entity Resolution)**:
  - 동일한 품번이지만 다른 엑셀에서 온 데이터들을 `part_number` (Merge Key) 기준으로 통합.
  - 유사한 공급사 명칭(예: "삼성전자", "삼성전자(주)")을 AI가 판단하여 하나의 노드로 병합 시도.

### [Step 6] 지식화 완료 및 활성화 (Activation)

- **데이터 헬스 체크**: 구축 완료 후 "도면이 누락된 부품 15개 발견", "공급사가 없는 핵심 품목 3개" 등의 리포트를 제공하여 데이터 보완 유도.
- **통찰력 제공**: 지식 그래프를 바탕으로 AI가 즉시 답변할 수 있는 추천 질문 목록 제공. (예: "이 프로젝트에서 가장 리스크가 큰 부품은?")

---

## 3. 핵심 설계 원칙

- **보안 우선**: 모든 데이터 인입 및 조회는 `org_id` 기반의 스키마 격리 환경 내에서만 이루어짐.
- **유연한 확장**: 표준 온톨로지를 강제하되, 유저의 특수 데이터는 `_ext_` 시스템을 통해 모두 수용.
- **가시성 제공**: 데이터가 '지식'으로 변하는 과정을 사용자에게 지속적으로 노출하여 서비스에 대한 신뢰 형성.
