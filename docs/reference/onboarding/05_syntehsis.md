# 🧬 Step 5: 데이터 지식화 및 합성 (Data Synthesis)

본 문서는 확정된 매핑 정보를 바탕으로 Raw 데이터를 정제하고, Apache AGE 그래프 내에 엔티티와 관계를 생성하는 백그라운드 프로세스를 정의합니다.

---

## 1. 개요 (Overview)

단순한 데이터 수집을 넘어, 서로 다른 출처의 데이터를 연결하여 '의미 있는 지식'으로 전환하는 단계입니다. 중복을 제거하고(Entity Resolution), 숨겨진 관계를 복원하여 팔란티어식 온톨로지 구조를 완성합니다.

---

## 2. 합성 파이프라인 (Synthesis Pipeline)

프로세스는 서버의 리소스를 효율적으로 사용하기 위해 **비동기 백그라운드 작업(Worker)**으로 실행됩니다.

### 2.1 단계별 로직

1. **스트리밍 데이터 로드 (Stream Load)**: R2 스토리지에서 파일을 스트리밍하며 한 행(Row)씩 읽어옵니다.
2. **데이터 유효성 검사 및 캐스팅 (Validation & Casting)**:
   - `Base Ontology`에 정의된 타입(Integer, Float 등)으로 데이터를 변환합니다.
   - 필수 필드가 누락되었거나 타입 변환이 불가능한 행은 에러 로그로 분류합니다.
3. **엔티티 병합 (Entity Resolution/Merge)**:
   - `is_merge_key=True`인 속성(예: `part_number`)을 기준으로 기존 노드가 있는지 확인합니다.
   - 이미 존재한다면 정보를 업데이트(`SET`)하고, 없다면 새로 생성(`CREATE`)합니다.
4. **관계 연결 (Linkage)**:
   - 매핑된 관계 설정(예: `CONSISTS_OF`)에 따라 노드 간의 엣지를 생성합니다.
   - 부모-자식 관계를 연결하여 계층 구조(BOM)를 형성합니다.

### 2.2 현재 API 규칙 (2026-02 기준)

- 다중 파일 합성 시작은 `POST /api/v1/projects/{project_id}/synthesis/batch`를 사용하며 `upload_ids` 배열을 받습니다.
- 서버는 매핑을 다음 우선순위로 선택합니다.
  - `project_id`에 연결된 최신 매핑
  - 없으면 조직 최신 매핑
- 각 파일은 백그라운드 Job로 등록되며, 업로드가 해당 프로젝트에 속하지 않으면 실패 항목으로 분리됩니다.
- 배치 진행상황은 `GET /api/v1/synthesis/batches/{batch_id}`로 조회합니다.
- 즉, 사용자에게 `mapping_id`를 노출하지 않아도 Item 생성이 가능합니다.

---

## 3. 엔티티 병합 전략 (Entity Resolution)

데이터의 일관성을 유지하기 위한 핵심 전략입니다.

| 상황               | 처리 방식                         | 비고                                            |
| :----------------- | :-------------------------------- | :---------------------------------------------- |
| **완전 일치**      | 속성 업데이트 (`MERGE`)           | `part_number`가 동일한 경우                     |
| **속성 충돌**      | 최신 데이터 우선 (Timestamp 기반) | 동일 부품에 대해 서로 다른 이름이 올 경우       |
| **유사 이름 (AI)** | 수동 병합 제안 또는 AI 자동 병합  | "삼성전자" vs "삼성전자(주)" 등                 |
| **확장 속성**      | 기존 속성에 추가                  | 정의되지 않은 새로운 `_ext_` 필드들은 계속 누적 |

## 4. 사용자 경험: 대기 및 진행 상황 (Progress UI)

지식화 과정은 시간이 소요될 수 있으므로, 사용자에게 실시간 피드백을 제공하여 시스템이 작동 중임을 인지시킵니다.

### 4.1 실시간 상태 대시보드

- **카운터 애니메이션**: 생성된 노드 수, 연결된 관계 수, 처리된 행 수 등을 실시간으로 노출.
- **로그 스트리밍**: _"Part 'ASM-001' 생성 완료..."_, _"BOM 계층 구조 4단계 연결 중..."_ 과 같은 마일스톤 로그 표시.
- **예상 소요 시간**: 데이터 크기를 바탕으로 남은 시간 계산 및 안내.

---

## 5. 기술적 구현 상세 (Technical Details)

### 5.1 Apache AGE 최적화

- **Batch Processing**: 매 행마다 쿼리를 날리지 않고, 일정 단위(예: 100행)로 묶어 Cypher 명령을 실행하여 DB 부하 최소화.
- **Index Utilization**: 인제스션 전, 온톨로지에 정의된 `is_indexed=True` 필드들에 대해 인덱스가 생성되어 있는지 자동 확인.

### 5.2 작업 큐 관리 (Task Queue)

- FastAPI의 `BackgroundTasks` 또는 전용 워커(예: TaskIQ, Celery)를 사용하여 API 응답과 데이터 처리를 분리.
- 작업 완료 시 사용자에게 알림(웹훅 또는 소켓 통신) 발송.
